## Problem and behavior

The county profile read schema/scan flags from county field rows, but the
producer normally stores those flags in the parent observation. A synthetic
Cass-shaped row therefore displayed `Unknown / Not scanned` next to
51,689 populated records out of 51,689 and 100.00%.

`gac_projection.py` joins shared flags with county measurements without changing
the saved observation. `dashboard.py` applies it for both modern and legacy
parcel observations and the generic address/road standards. Both county table
renderers and the Excel county-detail exporter use the same interpretation.
Public sanitization preserves explicit nulls for the two known boolean flags
so an intentional unknown cannot be replaced by shared metadata.

Acceptance preserves these distinctions:

- Explicit county false/unknown overrides shared metadata.
- Shared scan=true does not create a county measurement.
- Measured zero population remains scanned; a zero denominator has no percentage.
- Explicitly unscanned and unavailable population have no percentage.
- No statewide population count is substituted into a county row.
- Missing counties remain missing. Source observation clocks, provider behavior,
  coverage counts and percentage denominators are unchanged.

JSON county fields now carry nullable schema/scan flags. Population values
contradicting explicit false/unknown flags are suppressed in the presentation
projection. CSV and workbook column layouts are unchanged. For a legacy
workbook row with neither a scan flag nor a county measurement, the scan cell
is now blank/unknown instead of incorrectly false.
